# Chil Terrace Order

QRコードから注文できる、飲食店向けの注文・厨房管理システム。Next.js (App Router) + Prisma Postgres + NextAuth。

- **客側**: 運用方式に応じて2種類
  - 卓方式: `/order/[卓番号]`（実運用では卓に設置したQRコードから）。同じ卓のQRから複数人が別々に注文しても、店側では同じ卓（会計セッション）にまとめて表示される
  - 注文番号方式: `/order`（レジ・カウンター設置の共通QRから）。注文するたびに注文番号（本日の通し番号）が発行される。会計はこのアプリでは行わない前提（別システム）
- **店舗側**: ルートURL（`/`）が `/staff/login` にリダイレクトされる。ログイン画面から新規登録（アカウント作成）もできる
  - 注文管理（厨房ボード。卓方式は卓ごと、注文番号方式は番号ごとにステータス管理）
  - 売上ダッシュボード
  - 設定（一般・メニュー・テーブル・QRコード印刷・アカウント）

> ⚠️ ログイン画面の新規登録は誰でもアカウントを作成できる（招待制ではない）。URLを知っている第三者がスタッフアカウントを作成できてしまうため、公開後に無関係な登録が増えるようなら制限を検討すること。

## セットアップ

```bash
npm install
```

`.env.local` を作成し、`.env.example` を参考に環境変数を設定する（Postgres接続文字列はVercelでPostgresを接続すると自動生成される）。

```bash
npx prisma db push   # スキーマをDBに反映
npm run db:seed       # DBが空の場合のみ、スタッフアカウント・テーブル・メニューの初期データを投入
npm run dev
```

## 環境変数

`.env.example` を参照。主なもの:

- `DATABASE_URL` ほか — Postgres接続文字列（`src/lib/env.ts` が複数の命名パターンにフォールバック対応）
- `AUTH_SECRET` — NextAuthのセッション暗号化キー
- `STAFF_EMAIL` / `STAFF_PASSWORD` — 初回デプロイ時（アカウントが1件も無いときだけ）に作成される最初のスタッフアカウント。2件目以降は設定画面のアカウントタブから追加する
- `TABLE_COUNT` — 初回デプロイ時（テーブルが1件も無いときだけ）に作成するテーブル数

店舗名・運用方式（卓方式／注文番号方式）・メニュー・テーブル・スタッフアカウントは、すべて `/staff/settings` の設定画面からいつでも変更できる（DBで管理、再デプロイ不要）。

## 運用方式について

- **卓方式**: 席にQRコードを設置。注文は卓単位でまとめられ、会計（注文管理画面の「会計」ボタン）で締める。売上ダッシュボードは「確定売上（会計済み）」と「進行中の見込み」を分けて集計する。
- **注文番号方式**: 席を指定せず、注文ごとに本日の通し番号を発行する（フードコート形式）。会計はこのアプリの外（別のレジシステムなど）で行う前提で、決済機能は持たない。スタッフは「調理中」「受け渡し済み」のステータスのみを管理する。ダッシュボードの金額はあくまで目安表示。

設定画面（一般タブ）でどちらか一方をいつでも切り替えられる。過去の注文には発生時点のモードが記録されるため、切り替えても履歴の見え方は変わらない。

## デプロイ

Vercelに接続済み。`main` ブランチへのpushで自動デプロイされる。`vercel-build` スクリプトがデプロイの度に `prisma generate` → `prisma db push --accept-data-loss` → シード投入（データが無い部分のみ） → `next build` を実行する。
