# Chil Terrace Order

QRコードから注文できる、飲食店向けの注文・厨房管理システム。Next.js (App Router) + Prisma Postgres + NextAuth (Auth.js) で構築。

このREADMEは、実装済みの仕様をひととおり日本語でまとめたものです。コードの正としての役割は各ファイルのコメントが担い、ここでは「何ができるか」の全体像を把握できるようにしています。

## 全体構成

- ルートURL（`/`）は常に `/staff/login` にリダイレクトされる。客はQRコードから直接 `/order` または `/order/[卓番号]` にアクセスするため、ルートURLを客向けに使うことはない。
- 客側の画面（`/order`, `/order/[卓番号]`）はログイン不要。誰でもアクセスでき、アカウント作成は一切不要。
- 店舗側の画面（`/staff/*`）はログイン必須。未ログインでアクセスすると `/staff/login` にリダイレクトされる（`src/proxy.ts` によるガード）。各APIルートも個別にセッションを検証している（多層防御）。
- 店舗名・運用方式・メニュー・テーブル・シフトメンバー・スタッフアカウントは、すべてDBで管理され、設定画面からいつでも変更できる。**再デプロイは不要。**

## 運用方式（卓方式 / 注文番号方式）

設定＞一般（`/staff/settings/general`）で、店舗全体の運用方式をどちらか一方に切り替えられる。

### 卓方式（table）

- 各テーブルにQRコード（設定＞QRコードから発行・印刷可能）を設置する。同じ卓に複数人がいる場合は全員が同じQRを読み取る想定で、各自のスマートフォンから同時に注文してよい。
- 客がQRを読み取ると `/order/[卓番号]` が開き、その卓の注文画面になる。
- 同じ卓のQRから複数人が同時に（ほぼ同じタイミングで）別々に注文しても、進行中の「会計セッション」が同じであれば、店側では同じ卓にまとめて表示される（`TableSession`）。特に「その卓にとって最初の注文」が複数人からほぼ同時に送信された場合でも、DBのユニーク制約（`TableSession.openTableId`）により会計セッションが二重に作られることはなく、必ず1つのセッションに合流する。
- 客は注文するたびに新しい `Order` が作られ、同じセッションに紐づく。
- スタッフが注文管理画面で「会計」を押すと、その卓の未会計の注文がすべて `paid` になり、会計セッションが閉じる。
  - 会計が完了すると、その場でご注文中だった客の画面は自動的に「お会計ありがとうございました」というロック画面に切り替わり、それ以上注文できなくなる（次に来店する別のお客様の注文と混ざらないようにするための挙動。詳しくは後述）。
  - 次のお客様が同じ卓のQRを新たに読み取ると、通常通り新しい会計セッションが自動的に始まり、そこから注文できる。
- 売上ダッシュボードは「確定売上（会計済み＝`paid`）」と「進行中の見込み（まだ会計前）」を分けて集計する。

### 注文番号方式（number）

- レジ・カウンターに共通のQRコードを1枚設置する（フードコート形式）。
- 客がQRを読み取ると `/order` が開き、卓の概念なしに注文できる。
- 注文するたびに「本日の注文番号」（`OrderCounter` によるJST日付ごとの連番、日が変わると1から採番し直す）が発行される。
- **会計・決済機能はこのアプリでは持たない。** 会計は別のレジ／POSシステムで行う前提。スタッフは注文のステータス（受付／調理中／提供済み＝受け渡し済み）のみを管理する。
- 売上ダッシュボードの金額は「受け渡し済み（目安）」「対応待ち（目安）」として表示され、実際の会計金額とは独立している旨を明記している。

過去の注文には発生時点の運用モードが `Order.mode` として記録されるため、運用方式を後から切り替えても、過去データの集計や表示が変わることはない（ダッシュボードや分析画面は「現在の運用方式」の注文のみを対象に集計する）。

## 客側の機能

### 注文画面（`/order/[卓番号]` または `/order`）

- カテゴリタブ（おすすめ・フード・ドリンクなど、設定で自由に追加・変更可）で商品を切り替え。
- 各商品に `+` / `−` ボタンで数量を指定し、カートに追加。
- 下部固定バーに合計点数・合計金額・「注文する」ボタン。
- 注文すると即座にサーバーへ送信され、店舗側の注文管理画面にリアルタイム（数秒間隔のポーリング）で反映される。

### 注文履歴・合計（客側）

- **卓方式**: ヘッダーの「注文履歴・合計 ¥X」ボタンから、進行中の会計セッションで注文したすべての商品（会計済み・取消済みも含む）と合計金額を確認できる。取消された注文は取り消し線付きでグレー表示され、合計には含まれない。
  - 数秒おきのポーリングでスタッフ側の「会計」操作を検知しており、会計が完了した時点で画面全体が「お会計ありがとうございました」というロック画面に切り替わる。この画面ではそれ以上の注文操作（カート追加・注文送信）は一切できない。これは、会計済みの端末がそのまま操作を続けて新しい会計セッションを無自覚に開始してしまい、次に来店する別のお客様の注文と同じセッションに紛れ込む事故を防ぐための仕様で、ページを再読み込み（＝QRの再読み取り）しない限りロックは解除されない。
- **注文番号方式**: 注文するたびに大きく番号（例: `#12`）が表示され、その注文の内容と合計、現在のステータスがリアルタイムに更新される。「追加で注文する」でメニューに戻って続けて注文でき、同じブラウザで行った過去の注文はすべて記憶される（`localStorage`）。「これまでの注文履歴・合計」から、これまでの全注文とその合計金額を一覧できる。注文番号方式には会計・決済機能自体が無いため、このロック挙動はない。
- ページを閉じて再度QRを読み取っても、直近の注文状況・履歴は自動的に復元される。

## 店舗側の機能

すべて `/staff/login` からログイン後にアクセスする。ログイン画面には新規登録（アカウント作成）フォームもあり、招待コード・名前・メール・8文字以上のパスワードを入力するとその場でアカウントが作られ、自動的にログインされる。

新規登録には招待コードが必須（設定＞招待コードから既存スタッフが発行する）。コードは1回使うと失効し、任意で有効期限も設定できる。招待コード付きのURL（`/staff/login?invite=コード`）を共有すれば、リンクを開くだけで新規登録フォームが開きコードも自動入力される。

### 注文管理（`/staff/orders`）

- **卓方式**: 卓ごとにカードが並び、各カードに進行中の注文（受付・調理中・提供済み）が表示される。カード上部の「会計」ボタンを押すと、画面中央に確認モーダルが開き、注文内容・合計金額を確認してから「会計を確定する」で確定する（誤タップ防止のための2段階操作）。
- **注文番号方式**: 卓の概念がないため、進行中の注文（受付・調理中）が番号順にフラットに並ぶ。提供済み（受け渡し済み）になった注文はボードから自動的に消える。
- 各注文のステータスは「受付／調理中／提供済み」のピルボタンで**どれでも自由にタップして変更できる**。一方向にしか進めない仕様ではないため、ミスタップしても正しい状態に戻せる。「取消」でいつでもキャンセルできる。
- 6秒間隔で自動的に最新状態へ更新される（ポーリング）。

### 売上ダッシュボード（`/staff/dashboard`）

- 本日（JST基準）の集計をリアルタイムに表示。
- 卓方式: 確定売上／進行中の見込み／本日の注文件数／客単価／本日の会計卓数／取消件数。
- 注文番号方式: 受け渡し済み（目安）／対応待ち（目安）／本日の注文件数／客単価／受け渡し件数／取消件数。
- 時間帯別売上（1時間ごとの棒グラフ、昼の部＝17時未満／夜の部＝17時以降で色分け）と、昼夜の内訳円グラフ。

### 注文分析（`/staff/analytics`）

- 期間（本日／過去7日間／過去30日間）を切り替えて、人気メニューランキング（販売数トップ10）とカテゴリー別売上構成（円グラフ）を確認できる。
- 注文件数・期間売上・平均注文点数のサマリも表示。

### 期間分析（`/staff/reports`）

- 期間（過去7日／30日／90日）を切り替えて、日別売上の推移を棒グラフで確認できる。
- 期間合計売上・期間注文件数・客単価（期間平均）・取消件数のサマリも表示。

### シフト表（`/staff/shifts`）

- **月表示**（`?view=month`）: カレンダー形式で、日ごとに勤務予定のあるメンバー名と人数（「N人出勤」）を一覧できる。日付をクリックすると、その日の日表示に遷移する。
- **週表示**（`?view=week&date=YYYY-MM-DD`）: Microsoft Teamsの週ビューを意識した、メンバー×7日間の表形式。各セルにその日の勤務時間帯を短いラベルで表示し、クリックするとその日の日表示に遷移する（編集は日表示で行う）。
- **日表示**（`?view=day&date=YYYY-MM-DD`）: 時間軸×メンバー列のタイムライン表示。0:00〜24:00の時間軸を縦に、メンバーを横に並べ、勤務予定を時間の長さに応じたブロックとして表示する。本日を表示している場合は現在時刻を示す線が入る。終了時刻が開始時刻以前（例: 22:00〜2:00）の場合は日をまたぐ勤務として1件で登録でき、その日のタイムライン上は24:00までで表示を打ち切り、ラベルに「22:00–翌2:00」のように表示する。
  - 各メンバー列の「＋」ボタンから、開始時刻・終了時刻（`<input type="time">`）とメモ（任意）を指定して勤務予定を追加できる。
  - 既存のブロックをクリックすると編集・削除ができる。
  - その日全体への申し送りメモ欄がある（シフト内容とは別に、その日のスタッフ全員向けのメモ）。
  - 「印刷する」ボタンで、ナビゲーションなどの画面要素を隠した印刷用レイアウトで出力できる（月表示・日表示どちらも対応）。CSV・Excelでのダウンロードにも対応（月単位）。
  - 前日／翌日・前月／翌月・前週／翌週・「今日」「今月」「今週」への移動リンクあり。
- シフトメンバー（誰がシフトに入れるか）は、設定＞シフトメンバーで追加・名前変更・削除する。**ログインアカウントとは別の名簿**であり、シフトメンバーであること自体はシステムへのログイン権限を意味しない。

### 予約表（`/staff/reservations`）

来店予約を手動で記録する台帳（決済・注文とは連動しない）。シフトの日表示と同じ形式で、0:00〜24:00の時間軸に対して、卓方式のときは卓ごとの列（＋卓未定列）、注文番号方式のときは単一の列に、予約を時刻の位置のブロックとして表示する。ブロックをクリックすると、お名前・電話番号・人数・時刻・卓・メモ・ステータス（予約済み／来店済み／キャンセル／無断キャンセル）を編集できる。CSV・Excelでのダウンロードに対応（日単位）。

### 設定（`/staff/settings/*`）

タブ構成: 一般 / メニュー / テーブル（卓方式のときのみ表示） / QRコード / シフトメンバー / アカウント / 招待コード

- **一般**: 店舗名、運用方式（卓方式／注文番号方式）の切り替え、Wi-Fi案内（任意・客側の注文画面に表示）。
- **メニュー**: カテゴリーの追加・名称変更・削除（商品が残っているカテゴリーは削除不可）。商品の追加・編集（名前・価格・説明・おすすめフラグ・販売中フラグ・アレルギー表示・商品写真URL・価格改定の予約適用）・削除（注文履歴がある商品は削除不可。販売停止フラグで対応する）。印刷用の一覧表示、CSV・Excelでのダウンロードにも対応。
- **テーブル**（卓方式のみ）: 卓の追加・表示名の変更・削除（注文履歴がある卓は削除不可）。
- **QRコード**: 卓方式は卓ごとのQRコード一覧、注文番号方式は共通QRコードを1つ表示。「印刷する」ボタンで、店内掲示用にQRコードだけを大きく印刷できるレイアウトになる。QRのURLは環境変数 `NEXT_PUBLIC_APP_URL`（未設定時はリクエストヘッダーから推測）を基点にしており、Vercelのデプロイ固有URLなどではなく本番の正式ドメインを指す。卓ごとのURLにはランダムなトークンが含まれ、トークンが一致しない限り客側の注文画面・APIを拒否する。
- **シフトメンバー**: シフト表に表示するメンバーの追加・名称変更・削除。
- **アカウント**: ログインアカウントの一覧、追加（名前・メール・8文字以上のパスワード）、削除（最後の1件は削除不可）、パスワード再設定。
- **招待コード**: 新規登録に必要な招待コードの発行・無効化。コードは1回使うと自動的に失効し、任意で有効期限（日数）も設定できる。発行したコードは「コード付きURL（`/staff/login?invite=コード`）」としても共有でき、開くと新規登録フォームにコードが自動入力される。

## 認証・アカウント

- NextAuth (Auth.js) の Credentials プロバイダ + JWTセッションを使用。
- パスワードは bcrypt でハッシュ化して `StaffUser.passwordHash` に保存。
- ログイン画面から新規登録が可能（招待コードが必須。設定＞招待コードから発行する）。
- 設定＞アカウントから、既存メンバーがアカウントを追加・削除・パスワード再設定できる。
- 初回デプロイ時（アカウントが1件も無い場合のみ）、環境変数 `STAFF_EMAIL` / `STAFF_PASSWORD` から最初のアカウントが自動作成される（`prisma/seed.ts`）。

## データモデル

主要なテーブル（`prisma/schema.prisma` 参照）:

| モデル | 役割 |
|---|---|
| `StaffUser` | 店舗スタッフのログインアカウント |
| `StaffInvite` | 新規登録に必要な招待コード |
| `Settings` | 店舗名・運用方式などを1行だけ持つシングルトン |
| `RestaurantTable` | 卓方式で使うテーブル（QRトークン・スタッフ呼び出し状態を含む） |
| `Category` / `MenuItem` | メニューのカテゴリーと商品（アレルギー表示・商品写真URL・価格改定予約を含む） |
| `TableSession` | 卓方式の会計セッション（QRから会計までの一続き。卓メモを含む） |
| `OrderCounter` | 注文番号方式の、JST日付ごとの通し番号カウンタ |
| `Order` / `OrderItem` | 注文とその明細（明細は注文時点の商品名・単価をスナップショットとして持つ） |
| `ShiftMember` | シフト表のメンバー名簿（ログインアカウントとは独立） |
| `Shift` | 1件の勤務予定（メンバー・日付・開始時刻・終了時刻・メモ） |
| `DayNote` | シフト日表示に添える、その日全体への申し送りメモ |
| `Reservation` | 来店予約（手動入力の台帳、決済・注文とは非連動） |

`Order.mode`（"table" | "number"）と `Order.status`（pending → preparing → served → paid[卓方式のみ] / cancelled）が状態管理の中心。マイグレーションファイルは持たず、デプロイのたびに `prisma db push` でスキーマをそのまま反映する運用。

## 環境変数

`.env.example` を参照。主なもの:

- `DATABASE_URL` ほか — Postgres接続文字列（`src/lib/env.ts` が複数の命名パターンにフォールバック対応）
- `AUTH_SECRET` — NextAuthのセッション暗号化キー
- `STAFF_EMAIL` / `STAFF_PASSWORD` — 初回デプロイ時（アカウントが1件も無いときだけ）に作成される最初のスタッフアカウント
- `TABLE_COUNT` — 初回デプロイ時（テーブルが1件も無いときだけ）に作成するテーブル数
- `NEXT_PUBLIC_APP_URL` — QRコードに埋め込む絶対URLの基点（本番の正式ドメインを指定）

## セットアップ

```bash
npm install
```

`.env.local` を作成し、`.env.example` を参考に環境変数を設定する（Postgres接続文字列はVercelでPostgresを接続すると自動生成される）。

```bash
npx prisma db push   # スキーマをDBに反映
npm run db:seed       # DBが空の場合のみ、スタッフアカウント・テーブル・メニューの初期データを投入
npm run dev
```

### メニューを紙メニューの内容に一括更新する

`prisma/menu-data.ts` に現在の紙メニュー（「チルパリ 〜Terrace酒場〜 FOOD MENU」）の内容が定義されている。

- **新規環境**（DBにカテゴリーが1件も無い場合）: 上記の `npm run db:seed` で自動的にこの内容が入る。
- **すでに旧メニューが投入済みの環境**（本番など）: `npm run db:reset-menu` を実行すると、既存メニューを `prisma/menu-data.ts` の内容に一括更新する。注文履歴が無い商品は削除、注文履歴がある商品は削除できないため「販売停止」扱いにしたうえで、新メニューの内容を投入する（複数回実行しても安全）。実行前に `.env.local` の `DATABASE_URL` が対象の環境を指していることを確認すること。

## デプロイ

Vercelに接続済み。`main` ブランチへのpushで自動デプロイされる。`vercel-build` スクリプトがデプロイの度に `prisma generate` → `prisma db push --accept-data-loss` → シード投入（データが無い部分のみ） → `next build` を実行する。

## 既知の制約・今後の余地

- 会計・決済処理そのものは実装していない（卓方式の「会計」はステータスを進めるだけ、注文番号方式は最初から会計操作なし）。
- シフト表の時間帯は日単位の0:00〜24:00表示。終了時刻が開始時刻以前（例: 22:00〜2:00）の場合は日をまたぐ勤務として1件で登録でき、タイムライン上はその日の24:00までで表示を打ち切り、ラベルには「22:00–翌2:00」のように翌日である旨を示す。
- メニュー画像のアップロードには対応していない。設定＞メニューで外部にホストされた画像のURLを指定する方式のみ。
